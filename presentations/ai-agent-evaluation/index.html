A true story · February 2024

The $650 chatbot

  • A grieving customer asks Air Canada's website chatbot about bereavement fares.
  • The bot confidently invents a policy: "book now, claim the discount back within 90 days."
  • That policy never existed. Air Canada refused the refund.
  • In court, the airline argued the chatbot was "a separate legal entity responsible for its own actions."
$650

The tribunal rejected the "it's not us" defense — Air Canada paid CAD $650.88 in damages (≈$812 with interest & fees).

Moffatt v. Air Canada, 2024 BCCRT 149 · BC Civil Resolution Tribunal

The code worked perfectly. The answer was a lawsuit.

Hall of fame · expensive lessons

It wasn't a one-off

🚗 The $1 Tahoe

A Chevy dealership bot was talked into agreeing a 2024 Tahoe for $1 — and added "that's a legally binding offer, no takesies-backsies."

⚖️ Fake case law

A lawyer filed a brief full of citations ChatGPT invented. The cases didn't exist. The court issued sanctions.

🛫 The refund bot

Air Canada — same root cause: a confident model, an unverified answer, a real bill.

None of these had a bug. They shipped without evaluation.

First, the words

Four terms, no jargon

LLM — a Large Language Model. A text-prediction engine that's read most of the internet. Brilliant, fluent… and occasionally makes things up with total confidence.
Automation — a fixed recipe. "When email arrives → save attachment → notify Slack." Same steps every time. No judgment.
Agent — an LLM that decides and acts: it picks tools, takes steps, reacts to results to reach a goal. Judgment included.
Evaluation ("eval") — measuring, systematically, whether the agent is actually good: correct, consistent, safe, fast, affordable.

An automation you debug. An agent you evaluate.

Why your old test playbook fails

Calculator vs. moody intern

Traditional software

Deterministic. Same input → the same output, every single time.

assert add(2, 2) == 4 ✅
assert add(2, 2) == 4 ✅
assert add(2, 2) == 4 ✅

A calculator never has an off day.

VS

An AI agent

Non-deterministic. Same input → a different answer each run. Different words, different tools, different reasoning.

assert agent("refund?") == "..." ✅
assert agent("refund?") == "..." ❌
assert agent("refund?") == "..." 🤷

A smart intern who's brilliant on Monday, distracted on Friday.

Exact-match testing (==) is meaningless here. We need a new yardstick.

The mindset shift

"Did it pass?" is the wrong question

Does it pass often enough?

One failure might just be noise — a bad dice roll.

One success might just be luck — you got the good Monday.

So we run each case many times and think in probabilities & rates, not green/red checkmarks. Evaluation is statistics, not assertions.

What "good" even means

An agent can finish with zero errors — and still be wrong

So you must test three different things:

1 · Final Answer

Is the output correct, relevant, safe, on-tone? The thing the user actually sees.

2 · Trajectory

The journey: did it pick the right tools, in the right order, with the right arguments? A correct answer reached by luck is a time bomb.

3 · Retrieval (RAG)

Did it pull the right facts from your documents — or answer from imagination?

Air Canada nailed #1's grammar, skipped #3's facts. All three matter.

How to evaluate · part 1

The Golden Dataset

Golden dataset (eval set) — a hand-curated list of test cases. Each one = an input + the ideal output or expected behavior. Your "answer key."
  • Start small: 30–100 realistic cases beats 10,000 random ones.
  • Pull from real user questions, tricky edge cases, and known disasters.
  • Cover the boring and the adversarial (the bereavement question!).

Your eval set is worth
more than your prompt.

Prompts and models change weekly. A good answer key is the asset that survives.

How to evaluate · part 2

Okay — but who grades the answers?

⚙️ Code / rules

Exact checks: valid JSON? contains the order number? under 200 words?

Cheap · instant · objective

Can't judge "is this helpful?"

🧑‍⚖️ Humans

People read outputs and rate them. The gold standard for taste & nuance.

Trustworthy · catches subtlety

Slow · pricey · doesn't scale

🤖 LLM-as-Judge

Use a strong model to score another model's output against a rubric.

Scales to thousands · fast · ~human-level

Has biases (next slide!)

In practice: code for the objective stuff, LLM-as-judge for scale, humans to audit the judge.

LLM-as-Judge · the fine print

Your robot judge has opinions

Do it right

  • Give a rubric with clear criteria — not "is this good?"
  • Ask it to reason criterion-by-criterion, then score.
  • Demand structured output + a written rationale you can inspect.

Known biases (yes, really)

  • Verbosity bias — longer answers feel smarter, so they score higher.
  • Position bias — whichever option is shown first tends to win.
  • Self-preference — models quietly rate their own writing best. 😏

A judge with a rubric is a colleague. A judge without one is a vibe.

How to evaluate · RAG

RAG, graded like a library visit

Two jobs: the librarian fetches books (retrieval); you write the essay (generation).

Retriever — did it fetch right?

  • Context Recall — did it grab all the books it needed?
  • Context Precision — are the right books ranked at the top, not buried?
  • Context Relevancy — how much of what it grabbed is actually on-topic?

Generator — did it answer honestly?

  • Faithfulness — is every claim supported by the fetched books? (No making it up.)
  • Answer Relevancy — does it actually answer the question asked?

Air Canada had the right book on the shelf and quoted a different one it imagined → a classic faithfulness failure.

How to evaluate · keeping it good

Regression testing: fix one thing, break three

Regression test — re-run your whole golden dataset after any change (new prompt, new model, new tool) to prove you didn't break what already worked.
  • You tweak a prompt to fix Q14… and silently wreck Q3, Q7, Q22.
  • Without an eval set, you'd never know until a customer does.
  • Mature teams run the eval set automatically on every change (in CI).

♻️ The eval flywheel

Every real-world failure becomes a new permanent test case.

Your agent can never make the same mistake twice — and your golden set grows sharper with age.

The scorecard

No single number captures "good"

🎯

Accuracy

Is it correct & faithful to the facts?

🔁

Consistency

Same question, same quality — every time?

⚡

Response time

Latency. A perfect answer in 40s feels broken.

💸

Cost

Cents per call × millions of calls = real money.

😀

User satisfaction

Thumbs-up rate, escalations, re-asks.

💥

Failure rate

How often it errors, refuses, or goes rogue.

A 99%-accurate agent that's slow, pricey, and inconsistent can still be unusable.

The trade-off you can't escape

Quality · Cost · Speed — pick your balance

Qualitysmartest model
Costcheapest call
Speedlowest latency

The "smartest" model can be 10× the price and 3× slower. A fraud check wants quality; an autocomplete wants speed; a bulk classifier wants cost.

Match the model to the task — and let your eval scores prove the trade was worth it.

You don't build this from scratch

The toolbox (so the names aren't scary)

RAGAS

Open-source. Popularized the RAG metrics we just saw — faithfulness, context precision/recall.

DeepEval

"Pytest for LLMs." Write evals like unit tests; inspect why the judge scored what it did.

TruLens

Tracing + feedback functions to evaluate and debug agent runs.

Cloud & platforms

LangSmith, Braintrust, Maxim, Azure/Vertex eval — dashboards, regression runs, production monitoring.

Same ideas everywhere: a golden set, a grader, a scorecard, on repeat.

If you remember five things

The evaluator's checklist

  • Build the eval set before the agent. No answer key, no project.
  • Think in rates, not pass/fail. Run it many times.
  • Test the journey, not just the answer. Tools & retrieval too.
  • Use a judge — with a rubric. Watch for verbosity & self-preference.
  • Add every production failure back as a test. Feed the flywheel.

You can't improve what you don't measure — and with agents, measuring is the hard, valuable part.

Full circle

One faithfulness test.

That's all it would have taken to catch the Air Canada bot — before the $650, the lawsuit, and the headlines.

Evaluation isn't the boring part. It's the part that ships.
